The Engine Build Plan

From a proven corpus to a living engine — how augur ingests, classifies, remembers, discovers, and answers. The rungs, in order, and the gates that keep each one honest.

Forward Intelligence · By Cision

History doesn't repeat itself, but it often rhymes.

— attributed to Mark Twain

The back-test proved the method. It also drew the map: it named the one broken part — the keyword floor that mistook a pension story for motor finance — and the one thing missing for a clean proof — a derivation with no foreknowledge. Both are LLM-shaped holes. This plan fills them without forking the canon. Everything below hangs off the Cerebro pipeline you already designed; nothing here replaces it.

Part I

The pipeline we build on

augur already has a spine. Cerebro produces; augur remembers and reads forward. The build extends this skeleton — it does not draw a new one.

Intake Checkpoint — a human approves the edition before anything is remembered.
2

Raw .html lands governed, versioned, named client_YYYY-MM-DD.html. The long memory.

3

Deterministic parse (Stations 1–3) shreds stories into rows; Station 4 classifies. This is where the bounded LLM lands.

The Firebreak — a signal enters instantly; a pattern earns the right to shape future briefings only after mining and scoring.
4

Signals enter the ledger, mining finds rhymes, PathFinder issues dated, scored predictions.

The observation surface and the deliverable. Foresight folds back to Stage 1.

The line
Cerebro is augur's intake; augur is Cerebro's memory and foresight. The bounded LLM is Station 4 of Stage 3. The query librarian reads Stages 2–4. Discovery is a new loop hanging off the Signal Ledger. Every new piece clips onto a stage that already exists.
Part II

Two LLMs, two jobs, two trust models

The instinct is "add AI to augur." The discipline is to notice AI enters in two places, with opposite risk profiles — and to never let them blur. The single rule that binds them: classify once, at write time, and freeze it. The librarian reads what's frozen; it never re-judges on the fly. That is the arrow of time applied to classification — without it, the ledger is a moving target and no back-test is reproducible.

The bounded LLM, concretely. Not a chatbot improvising the parse. Stations 1–3 stay deterministic BeautifulSoup and hand it a clean, already-extracted signal — headline + section/lane + sub-entity + source + date. It answers exactly the two questions the keyword stub fakes:

  • SignalType — one term from a controlled enum, or unclassified.
  • Event vs. mention — a fresh event, or an article referencing something older? (article date vs. referenced-thing date).
Acceptance
Run the held-out week back through it: the three phantoms — the UK–Japan deal, the KKR EV debt, the Scottish Widows pension-redress story — drop out, while the real 23 June FCA bark survives. The back-test is the bounded LLM's own acceptance test. If P4 doesn't reproduce that, it isn't bounded enough.
Part III

The capacity for the new

Everything proven so far is a matching engine — "have I seen this rhyme?" Discovery is the opposite motion — "is a new rhyme establishing itself?" The design has the bones; the mechanism is still manual, and it looks in the wrong place.

The move
Novelty does not live in the matched signals. It lives in the residue — the signals that matched nothing. The residual bucket is the nursery where new patterns gestate, not waste to be swept up.
Tier 1New instance of a known patternSolved

A fresh rhyme in a scheme augur already holds — another post-MPC repricing. This is matching; it is what the back-test scored.

Engine: keyword / matching (have it today).
Tier 2New pattern from known vocabularyBones exist

A theme we can name starts recurring enough to earn pattern status. AI-and-jobs is exactly this — it wasn't authored, it earned the meter by recurring. Done once, by batch mine.

Engine: frequency + co-occurrence mining over the relational ledger.
Tier 3Genuinely novel theme, no vocabularyFrontier

Something the tagger has no words for, because it has never happened. A keyword floor is structurally blind here — it can only find novelty made of words it already knows.

Engine: semantic — embeddings + clustering (the vector store), fed by the bounded LLM's unclassified route.

Where the bounded LLM becomes a discovery instrument. Give it one more permitted output — unclassified — and classification and novelty-detection turn out to be the same action seen from two sides. The keyword stub can't say "I don't recognise this"; it forces everything into a known box (which is how the Scottish Widows phantom happened). Every honest "I don't know what this is" is a candidate for a pattern we haven't named yet — routed into the nursery.

Discovery is

A hypothesis generator. A discovered pattern is born experimental, provenance mined, candidate-only — it cannot issue a prediction. It earns promotion the one way every pattern must: frozen, then scored forward.

Discovery feeds the back-test loop: mine the residual → propose → freeze a prediction → score it → promote or retire.

Discovery is not

A finding. A pattern noticed after the fact in existing data can never be wrong — that is a coincidence wearing a signal's clothes. The more aggressively you hunt, the more you "find," and most is noise.

The tell of the vicious loop: confidence climbing while the scorecard stays flat. Discovery is the most dangerous capability in augur, so it inherits the firebreak doubled.

The brake
Discovery runs as a periodic mine (weekly / monthly), not on every ingestion. The cadence itself is a guardrail against hyperactive agency — and a human christens or dismisses every candidate at the promotion gate.
Part IV

The rungs, in order

Sequenced so each rung unblocks the next, and so the highest-leverage build — the write path — comes early, because four other things hang off it. Two tracks run in parallel: the write path (the serious build) and the librarian (momentum from day one on what's already indexed).

0
HTML backfill — grow the long memory
Track: corpus · no code
Do now

Re-save the back-catalogue editions as HTML into the LBG HTML folder, then keep adding subsequent editions. This routes the long history through the same machine-readable front door we already proved — no PDF-parsing detour.

Depth is what discovery needs: a seven-week window can't reveal a quarterly or seasonal rhyme because the second occurrence isn't in the data. The deeper corpus is where slow patterns become visible.

Done whenThe full LBG back-catalogue sits in the HTML folder, Glean-indexed, ready for one corpus-agnostic write path to replay.
1
The bounded-LLM write path — Station 4
Track: write · the load-bearing build
Do now

Build the ingestion flow: Power Automate reads an edition's HTML, deterministic Stations 1–3 parse it, the bounded LLM classifies each signal (SignalType + event-vs-mention + unclassified), and the result writes to the Signals list.

  • Inputs are the parsed fields, not the whole briefing — it classifies, it doesn't roam.
  • Structured JSON, enum-constrained, temperature 0, one signal at a time.
  • The write path is corpus-agnostic: same Station 4 whether the front door is new Cerebro HTML or the replayed back-catalogue.
Done whenP4 re-run over the held-out week drops all three phantoms and keeps the real FCA bark — the back-test as acceptance test.
L
Query librarian, step 1 — RAG over the corpus
Track: read · zero dependencies
Parallel now

A Copilot Studio agent with the SharePoint document library as a knowledge source. Answers "what did we say about motor finance, and when" / "show me the AI-and-jobs thread." Read-only, no flows, no firebreak risk — works today on what's already indexed, and teaches you how analysts actually phrase questions.

Done whenAn analyst can interrogate the briefing archive conversationally, every answer traceable to an edition.
2
Backfill, cleanup & the zero-foreknowledge re-test
Track: write · three payoffs, one path
Next

Run the write path backward over the archive. One build does three jobs: it populates the Signals list from the corpus, cleans the phantoms the keyword stub planted, and — if the agent re-derives from the cleaned ledger — produces the leak-proof proof the canon flagged as the next rung.

Depends on: Rung 1 (the write path) + Rung 0 (the depth to replay).
Done whenA zero-foreknowledge derivation reproduces the 7/8 result — augur scoring itself, not the analyst scoring augur.
3
Query librarian, step 2 — structured flows
Track: read · the ledger, queryable
Next

Give the librarian hands: small Power Automate flows it calls with parameters, each mapping 1:1 to an ontology Action and emitting an audit row.

  • GetSignals(filter) — OData on indexed columns only (SignalDate, Category, Lane, Client, State). Never pull the whole list.
  • GetActivePatterns(date) — the Pattern Watch query already wired into the LBG Signscape agent.

Why flows, not direct List reasoning: scale. You're at 1,167 signals from 39 editions; a year × several clients is tens of thousands of rows, well past the 5,000-item view ceiling.

Depends on: Rung 2 (a populated Signals list to query).
Done when"What motor-finance regulatory signals fired in the last 18 months?" returns rows with citations, not prose from imagination.
4
The discovery loop — the nursery
Track: discover · Tier 2 first
Later

Stand up the residual bucket (a home for unclassified signals) and a periodic mine over it: frequency + co-occurrence thresholds for Tier 2, with the human-in-the-loop promotion gate — the agent surfaces "these signals are clustering; name it?", the analyst christens a candidate or dismisses it.

Tier 3 (semantic emergence / vector store) is a deliberate later rung — reach genuinely-novel themes once Tier 2 is proven and the corpus is deep enough to cluster meaningfully.

Depends on: Rung 2 (clean ledger) + Rung 0 (depth). Tier 3 adds the vector engine.
Done whenA candidate pattern, born experimental, survives a frozen forward score and is promoted by a human — discovery feeding the loop, not bypassing it.
5
Drafting tools — gated
Track: read+write · the firebreak as config
Later

Let the librarian draft, never commit. DraftPrediction / DraftCandidatePattern write in open / experimental state only. PromoteToPattern and ScorePrediction stay analyst-witnessed — the agent tees them up, a human commits. The firebreak, encoded as configuration.

Depends on: Rung 3 (flows) + Rung 4 (something worth drafting).
Done whenThe agent can draft a Pattern Watch lane and propose a candidate, and a human's click is the only thing that makes either real.

The shape of it

One write path, three loops, one librarian

You don't build an ingestion pipeline, then a backfill, then a cleaner, then a discovery engine. You build one bounded write path and run it forward (each new Cerebro edition) and backward (replay the archive) — and it populates the ledger, kills the phantoms, enables the zero-foreknowledge re-test, and feeds the nursery, all at once. The librarian reads what the write path makes clean. The discovery loop mines what it can't classify. And the firebreak stands at every gate, so emergence can propose but never manufacture fate. Start now with Rung 0 and the RAG librarian; the write path is the serious build everything else hangs off.
